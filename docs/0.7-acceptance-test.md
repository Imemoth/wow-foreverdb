# ForeverDB 0.7 acceptance test

## Versions under test

- Addon: **0.5.0-alpha**
- SavedVariables/export schema: **9**
- Companion: **0.8.2-alpha**
- Forever interface target: **16001**

This is the active acceptance checklist for the 0.7 map UX milestone. The current
Companion baseline is 0.8.2-alpha and includes the completed 0.7.2 Search zone-scope
work while the remaining 0.7.2 map-art tasks stay open.

## 1. Addon/export sanity

1. Run the current addon updater/copy step.
2. Start WoW Forever or run `/reload`.
3. Confirm chat/debug output reports the current addon version and schema 9.
4. Run `/fdb status`.
5. Generate at least one location-backed observation.
6. Run `/reload` or log out so SavedVariables are flushed.

Expected:
- the export contains schema 9;
- the new observation is present;
- map metadata exists for the current zone when the client exposes it.

## 2. Companion sync

1. Start the current Companion 0.8.2-alpha build.
2. Confirm the WoW path points at the Forever branch.
3. Trigger a SavedVariables write.
4. Confirm the Companion reports a successful authenticated sync.

Expected:
- anonymous authentication succeeds;
- the current snapshot is uploaded through the authenticated ingest RPC;
- map metadata is merged locally;
- sync remains successful even if background map pre-warming fails.

## 3. Map asset resolution

Open a detail result with location observations.

Expected preferred path:
- the matching WoW product/build is selected;
- map tiles resolve from local CASC when available;
- streamed/missing tiles may fall back to the exact installed build on Blizzard CDN;
- decoded tiles are stitched into a PNG cache;
- the status reports the resolved storage/asset mode.

Known validated zones:
- Tirisfal Glades: 12/12 tiles
- Silverpine Forest: 12/12 tiles

Expected fallback:
- if map art cannot be resolved, the normalized grid remains visible;
- markers, clusters and heatmap continue to work;
- a diagnostic status explains the failed resolver stage.

## 4. Multi-zone location UX

Use an item/source that has observations in more than one zone.

Verify:
- all observed zones remain selectable;
- selecting a location row changes the active map to that row's zone;
- the current zone/map selection is obvious;
- reopening a previously resolved map is effectively instant from cache.

## 5. Map interaction

Verify:
- mouse wheel zoom works across the supported range;
- left-drag pans when the map is larger than the viewport;
- Fit returns to full-map view;
- Markers, Clusters and Heatmap modes can be switched without re-resolving map art.

## 6. Marker/cluster semantics

Markers:
- show area/subzone when known;
- show coordinates;
- show acquisition kind;
- show observation/sample count.

Clusters:
- combine nearby weighted points;
- show unique-node and observation counts;
- do not discard observation weighting.

Fishing pools:
- display as Fishing Pool rather than generic Object;
- synthetic/internal IDs are hidden from normal UI.

## 7. UI regression

Verify:
- a selected location row remains dark/readable when keyboard focus moves to the map;
- map mode controls, Retry map and zoom percentage remain visible without horizontal clipping;
- the Locations Kind column uses readable labels such as `Fishing Pool`.

## 8. Navigation regression

Verify:
- starting from a new Search result resets the previous navigation chain;
- Back / Forward remains coherent within the active result chain;
- breadcrumb does not retain stale entries from the previous search result.

## 9. Search zone-scope regression

Use a query that has different coverage across observed zones.

Verify:
- the selector contains only actually observed zones plus an explicit `All zones`;
- `All zones` preserves the existing name and numeric-ID search behavior;
- changing from `All zones` or one zone to another automatically reruns a
  non-empty query without requiring the Search button;
- an empty Search box does not issue a search merely because the zone changes;
- the result list reflects the selected zone while opening a result still exposes
  its normal multi-zone detail/location data;
- a zero-result scope clears the previous result selection, detail panel,
  breadcrumb and Back/Forward navigation state instead of leaving stale detail
  from the previous zone;
- a slower earlier search cannot overwrite the UI after a newer zone selection.

### Diagnostic result and exact-build compatibility fix on PR #21

The second Windows screenshots establish that the active client is
`1.60.1.70245`. Only `1.60.1.70009` was allowed by the original
implementation. Two independent generated WoW DB2 overlay datasets
(jonlipin/Map Tab 70009 and cjber/tweaks-forever 70245) contain the same
complete numeric art/region/FileDataID records: 84/1,073/1,739, 0 differences.
No foreign GPL code or texture assets were copied.

The PR now accepts **only 70009 and 70245**, using the same atlas resource,
and retains exact-active-build CDN. For other builds the reason remains visible
even when the base map loads from cache. **The new code still requires a real
Windows/WoW acceptance rerun; successful static comparisons do not prove that
all BLP tiles can be read and displayed by the user's installation.**

The updated branch was tested successfully in a third live screenshot set
(see below). The build version error is resolved; the remaining manual
regressions are cluster/heatmap, geometry/tooltip precision and a cold
`Retry map` rebuild. Do not merge until final acceptance is reviewed.
