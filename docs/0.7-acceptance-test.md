# ForeverDB 0.7 acceptance test

## Versions under test

- Addon: **0.5.0-alpha**
- SavedVariables/export schema: **9**
- Companion: **0.8.2-alpha**
- Forever interface target: **16001**

This is the active acceptance checklist for the 0.7 map UX milestone. The current
Companion baseline is 0.8.2-alpha and includes the completed 0.7.2 Search zone-scope
work while the remaining 0.7.2 map-art tasks stay open.

## 1. Addon/export sanity

1. Run the current addon updater/copy step.
2. Start WoW Forever or run `/reload`.
3. Confirm chat/debug output reports the current addon version and schema 9.
4. Run `/fdb status`.
5. Generate at least one location-backed observation.
6. Run `/reload` or log out so SavedVariables are flushed.

Expected:
- the export contains schema 9;
- the new observation is present;
- map metadata exists for the current zone when the client exposes it.

## 2. Companion sync

1. Start the current Companion 0.8.2-alpha build.
2. Confirm the WoW path points at the Forever branch.
3. Trigger a SavedVariables write.
4. Confirm the Companion reports a successful authenticated sync.

Expected:
- anonymous authentication succeeds;
- the current snapshot is uploaded through the authenticated ingest RPC;
- map metadata is merged locally;
- sync remains successful even if background map pre-warming fails.

## 3. Map asset resolution

Open a detail result with location observations.

Expected preferred path:
- the matching WoW product/build is selected;
- map tiles resolve from local CASC when available;
- streamed/missing tiles may fall back to the exact installed build on Blizzard CDN;
- decoded tiles are stitched into a PNG cache;
- the status reports the resolved storage/asset mode.

Known validated zones:
- Tirisfal Glades: 12/12 tiles
- Silverpine Forest: 12/12 tiles

Expected fallback:
- if map art cannot be resolved, the normalized grid remains visible;
- markers, clusters and heatmap continue to work;
- a diagnostic status explains the failed resolver stage.

## 4. Multi-zone location UX

Use an item/source that has observations in more than one zone.

Verify:
- all observed zones remain selectable;
- selecting a location row changes the active map to that row's zone;
- the current zone/map selection is obvious;
- reopening a previously resolved map is effectively instant from cache.

## 5. Map interaction

Verify:
- mouse wheel zoom works across the supported range;
- left-drag pans when the map is larger than the viewport;
- Fit returns to full-map view;
- Markers, Clusters and Heatmap modes can be switched without re-resolving map art.

## 6. Marker/cluster semantics

Markers:
- show area/subzone when known;
- show coordinates;
- show acquisition kind;
- show observation/sample count.

Clusters:
- combine nearby weighted points;
- show unique-node and observation counts;
- do not discard observation weighting.

Fishing pools:
- display as Fishing Pool rather than generic Object;
- synthetic/internal IDs are hidden from normal UI.

## 7. UI regression

Verify:
- a selected location row remains dark/readable when keyboard focus moves to the map;
- map mode controls, Retry map and zoom percentage remain visible without horizontal clipping;
- the Locations Kind column uses readable labels such as `Fishing Pool`.

## 8. Navigation regression

Verify:
- starting from a new Search result resets the previous navigation chain;
- Back / Forward remains coherent within the active result chain;
- breadcrumb does not retain stale entries from the previous search result.

### PR #21 follow-up fix — code complete, Windows retest OPEN

The zone-change event now runs a **navigation-preserving** search refresh.
It retains the displayed detail and the Back/Forward stacks, suppresses
the programmatic `SelectionChanged` event, and reselects the result by
stable item ID or source type/ID/level when available in the new result
set. The most recently *explicitly selected* result remains remembered
when excluded by a scoped result list, so its highlight can return on
a later All zones / matching-zone refresh. If no longer in scope, the
side list correctly has no selected row while the detail remains visible.
A failed scoped RPC preserves the last usable results and navigation;
an explicitly started new search still resets the navigation session
as before. Stale parallel RPC responses are filtered by `_searchVersion`.

  exact-build CDN before displaying the revealed variant.

  Build Key+atlas fingerprint (14 days); failure retry is 15
  minutes or immediate via Retry map. Negative states never
  grant art verification; keep base map and correct markers.

## 14. Cycle-safe item/source drilldown navigation (PR #21)

**2026-10-09: CODE + CI PASS, real Windows cyclic navigation VISUAL PASS.** Search-zone regression suite **63/63 PASS** (including 21 focused cycle/history assertions). Screenshot-based Back navigation, distinct source drilldown and preserved cross-zone detail PASS. Direct Forward-click and rapid switch/in-flight request stress tests are **NOT YET VERIFIED**.

User screenshots showed repetitive breadcrumb growth when a detail link
returned to an already visited source/item: examples include a
`Peacebloom item #2447 → Peacebloom object #1618 → Peacebloom item`
loop and `Copper Ore → Copper Vein → Shadowgem → Copper Vein`.
The previous WPF code treated every detail-grid double-click as a
new deeper breadcrumb, producing chains such as
`Peacebloom › Peacebloom › Peacebloom › Peacebloom`, even though
the user was actually retracing the same item/source relationship.

**New semantics (browser-style):**

- A never-before-visited item or source adds exactly one Back entry
  and clears Forward, as previously.
- A link to the **current entity** is a no-op; it does not add
  another crumb or make a redundant HTTP detail request.
- A link to an entity already present in **Back** moves back to
  that entry (even across multiple levels), placing undone
  entries into **Forward**, instead of appending a duplicate.
- A link to an entity already in **Forward** moves forward to
  that entry, preserving the intervening navigation path.
- Item identity uses item ID; source identity uses
  source type + source ID + level, **not display name**.
  The herb *item* named Peacebloom and *Object* named Peacebloom
  remain correctly distinguishable.
- Back/Forward buttons and breadcrumb rendering share the exact
  same history transition logic. Existing zone-only browse and
  automatic zone refresh do not reset the detail navigation chain.
- The most recent async detail response alone may render the detail
  panel. Older in-flight requests are discarded if the user navigates
  again or explicitly starts a fresh search.

In other words, `Copper Ore → Copper Vein → Shadowgem → Copper Vein`
now acts as an explicit **Back** from Shadowgem to Copper Vein;
subsequent `Copper Ore` follows Back again, with Copper Vein and
Shadowgem available via **Forward** rather than nested repeatedly.

Portable `tests/companion-search-zone` includes cases for
item↔source backtracking, repeat/no-op clicks, jumping over multiple
ancestors, reusing existing Forward entries, Back/Forward buttons,
new branches invalidating Forward, and equal names but different
item/source identities and creature levels/types.

3. Branch to a genuinely different entity after Back:
