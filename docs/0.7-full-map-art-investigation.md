Status on 2026-10-08: **repo-side implementation proposed in PR #21; CI/build verification and real Forever/Windows acceptance OPEN.** Do not mark runtime PASS before observing it.

## Why one static map backdrop is possible

The WoW Forever 1.60.1 map uses the native `C_Map` base artwork as its **unexplored** appearance, with additional `WorldMapOverlay`/exploration tiles composited above it to show a discovered area. `C_MapExplorationInfo.GetExploredMapTextures(mapId)` only returns those overlays discovered **by the current character**. Thus the complete image is not necessarily another `MapArtID`: it is the **same base art plus all exploration overlays for that MapArtID**, irrespective of player exploration.

This is already demonstrated by the independent [Map Tab](https://github.com/jonlipin/map-tab) WoW Forever addon. Its MIT-licensed `Data/MapOverlays.lua` was generated from Forever's own `WorldMapOverlay` and `WorldMapOverlayTile` DB tables, build **1.60.1.70009**; it contains **84 MapArtIDs, 1,073 overlay regions and 1,739 tile FileDataIDs**. Original source blob: `13cafe8ee9f84a4015a636c48f134ce9bdcd4e67`. Copyright notice: [third-party map metadata attribution](third-party-map-atlas-notice.md). The map image assets themselves are **not** shipped with ForeverDB.

## What PR #21 changes

- A build-pinned local resource `Resources/FullRevealOverlays-70009.json` stores only numeric map-art IDs, offsets, regions and tile IDs. It is embedded in the Companion (no standalone addon install required).
- `FullRevealMapArt` reads that resource only for exactly `1.60.1.70009`, composites every BLP overlay on the unmodified native base canvas using alpha blending, respects 256px row-major layout, trims padded right/bottom tiles and clips to the canvas.
- The compositor is **transactional**. If any required texture cannot be read/decoded, it rejects the full variant and uses the previous base-art pipeline instead of displaying an incomplete/partially revealed collage.
- The selected map layer must match the verified **1002 x 668 / 256px tiles** layout and all base tiles must decode; otherwise it falls back. Other builds/layouts stay on the proven base art until their atlas/geometry is validated.
- Base art remains **local CASC first** -> active exact-build Blizzard CDN -> legacy named-texture path -> normalized grid. Missing reveal overlays can additionally try the **same installed build's** CDN without loading other builds.
- Successful and negative resolution caches are partitioned by `base` vs the pinned full-art variant, resolver version, build fingerprint, map/layer/texture refs; PNG filenames now include the resolution key, so old base PNGs cannot shadow the new variant. `Retry map` also clears actual PNGs, not only JSON resolution records.
- No changes to `MapPreviewControl`'s X/Y projection, marker, cluster, heatmap, tooltip, zone selector, breadcrumb or navigation logic. The composed image is an ordinary `MapAssetResult.Image` replacement.

## Future extension

New client builds require regenerating the overlay atlas **from that build's** WorldMapOverlay and WorldMapOverlayTile data, updating the pinned version/resource/variant ID, checking layer dimensions, and rerunning Windows acceptance. Do not use FileDataIDs from an unverified newer/older build. No remote art is redistributed by ForeverDB.
