# Guildbook Local-Only V1

The Companion stores Guildbook snapshots only at `%LOCALAPPDATA%\ForeverDB\guildbook\`, in an account/install namespace. Snapshot envelopes are protected with Windows DPAPI `CurrentUser` and committed atomically with a recoverable previous generation.

The WoW addon's SavedVariables file remains a separate local source and is not DPAPI-protected. It can contain the raw Guildbook export, so filesystem access to the WoW profile must be treated as access to that source. The Companion never includes those fields in the public observation payload and does not call a Guildbook RPC.

Account sign-out clears the in-memory view but preserves encrypted files. A different account uses a different namespace and cannot load the previous account's snapshot; an old capture is rejected after an account switch.

Migration 0018 is compatible with both the current production schema and the
future 0016/0017 schema. It may be deployed independently after the legacy
private ingest implementation exists; the normal migration runner must record
it in the ledger. It revokes every existing account-Guildbook RPC discovered in
the catalog and projects both legacy public ingest paths to observation-only
data while preserving existing Guildbook rows. It can be applied independently
to the current production schema. For a future database that also receives the
pending account migrations, apply 0016, then 0017, then 0018 last, so no newly
created account RPC is briefly re-enabled after the kill switch.

An old client can still transmit Guildbook fields before the server migration
is applied. The server-side projection prevents those fields from being stored,
but cannot retract or prevent that legacy network transmission. No live
Supabase migration has been applied by this PR.
