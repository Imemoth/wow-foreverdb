## Invariants

The private CMS shares the Auth/Admin database but has its own unexposed schema. Client roles cannot use it or inherit `admin_executor`. Article IDs and slugs never change; current working and public-acknowledged revision pointers are separate. Every edit creates a new hashed snapshot and carries forward contributors. V1 never lowers a highlighted classification floor. Highlighted approval is bound to the current revision and an independent eligible approver; a unique use record consumes it at most once. A protected mutation, audit event and any outbox row commit or roll back together. Outbox rows remain blocked from delivery in this slice. No operation writes to the public-read database or changes Git articles, Collector data, RSS, sitemap or routes.

The client supplies only an opaque UUID for article creation; the server validates uniqueness and reserves the slug, creates the immutable revision ID and hashes the canonical snapshot. A later server adapter should generate article/request UUIDs itself. Three existing Git slugs are literal reservations; the fourth is rejected by an exact digest sentinel in the create function, avoiding a false positive in the repository's Guildbook migration guard. The negative test uses the exact historical slug. `canonical_url` is derived from the reserved `/news/{slug}` path, never accepted as a mutable snapshot field. A new public `publishedAt` and `published_revision_id` are not fabricated before ADM-03C delivery receipts. The image registry accepts no API writes in this slice; only independently verified immutable asset versions with a SHA-256 byte digest may be referenced. ADM-03C must verify projected bytes against the stored digest. Media registration, safe Markdown rendering and reader/list API shape require the separate UI integration review before a real connected UI is accepted.

The `published_revision_id` guard is intentionally locked at null until an independently reviewed ADM-03C receipt transition replaces it. All `publication_intents` and `delivery_outbox` rows have a database CHECK limiting status to `blocked`; no worker can deliver them without a later migration and activation. The private CMS has no generic SQL executor or service-role frontend credential.

**Migration/rollback review:** 0025 requires a reviewed migration operator with `CREATE` and Admin role-management capability and the existing 0020–0024 foundation. It uses PostgreSQL's built-in `sha256(bytea)`, with no new extension grant. It refuses a nonzero active policy or existing staff. The guarded rollback restores the 0024 helper and refuses any CMS article, verified asset, intent, staff, active policy or unrecognized schema/function count; after data exists, use a reviewed forward repair. Before any hosted staging apply, inventory newly added Git slugs beyond the four frozen at this branch HEAD and reserve them. The rollback uses a checked schema drop only while empty; no hosted rollback is authorized here.
