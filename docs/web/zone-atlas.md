# Zone atlas & observation maps (P2-Z1)

One reusable, Cloudflare-backed map engine serving two experiences, behind a gate that is **off by default**:

| Surface | What it shows |
| --- | --- |
| `/zones` | every atlas **zone (45)** and **capital city (6)**, whether or not anything was observed there |
| `/zone/<uiMapID>` | the zone's real artwork + all eligible published observations (category filters, clusters, details) |
| `/object/<id>`, `/creature/<id>`, `/fishing/<id>` | the **same** map engine, only that source's published locations; zone selector for multi-zone sources; link to the full zone map |

Not included (by design): the interactive World Map, continent-to-zone graphical navigation, dungeon/raid interiors, new artwork extraction, item drop coordinates.

## Feature gate and isolation

| Setting | Effect |
| --- | --- |
| `AZERDEX_ZONE_MAPS=1` (runtime, server) | enables the catalog directory, the map on `/zone/[id]` (incl. atlas zones without observations), the maps on source pages and the CSP widening below. **Unset = every page is byte-for-byte the previous behaviour.** |
| `NEXT_PUBLIC_AZERDEX_ASSET_BASE_URL=https://azerdex-assets.pages.dev` (**build time**) | the CDN origin (allow-list: `azerdex-assets.pages.dev`, `assets.azerdex.com`). Unset = no artwork origin: pages show an explicit "no artwork origin configured" state and the plain grid. Changing it needs a rebuild/redeploy. |
| `AZERDEX_ATLAS_CATALOG=snapshot` (optional) | never fetch the CDN catalog at runtime; use the bundled snapshot (hermetic CI / offline previews). |

CSP: when the gate is on and the origin is configured, the validated CDN origin (allow-list in `asset-url.ts`, https only, no wildcard/port/userinfo) is added to `img-src` and `connect-src` of **every HTML document**, not only the map routes. Reason: a CSP belongs to the document, and Next.js client-side navigation (clicking a `<Link>`) never fetches a new one, so a visitor who lands on `/`, `/zones`, `/database` ... and then clicks through to a map keeps the first page's policy; with the earlier route-narrow rule the browser blocked the manifest and images (`connect-src 'self' https://challenges.cloudflare.com`) until a hard reload. `script-src`/`style-src`/`default-src` (nonce, no `unsafe-inline`) and every other directive are untouched, and with `AZERDEX_ZONE_MAPS` unset (Production today) the policy is unchanged (unit and browser tested: `assetOriginForPage`, `tests/zone-maps/soft-navigation.spec.ts`). `/poc/maps/*` keeps its own rule. The CDN sends `Access-Control-Allow-Origin: *` on `/forever/*` and `/atlas/*`; the browser enforces it (tested with a real HTTPS server on the allow-listed host name, not a mocked response).

Production is not touched by this change. Activating it anywhere is a deliberate owner step (see *Activation*).

## Architecture

```
atlas catalog (CDN atlas/index.json, validated; bundled verified snapshot as fallback)
   └─ lib/maps/atlas/{schema,catalog-loader,catalog,zone-catalog}.ts      uiMapId is the identity
public read model (web_api.*)                                            observations, never artwork
   ├─ source():        locations of one source          (existing)
   └─ zone_map_points: published cells of one zone      (0002, NOT applied anywhere)
adapters: lib/maps/observation-adapters.ts  (validate; drop item/disenchant/invalid)
engine:   components/maps/ZoneMap.tsx  ->  ZoneMapViewer.tsx (the ONLY Leaflet user)  +  MapFilters + ZoneMapDetails
          variants: "zone" (overview + filters)  /  "source" (compact, one source)  — ZoneMapPoc is a thin wrapper
coordinates: lib/maps/coordinates.ts (unchanged; the only conversion code)
```

* `ZoneMap` loads and validates the manifest on the client, then cross-checks it with the catalog: manifest `zoneId` = this uiMapID, `version` = the catalog's latest immutable version, image size = the catalog's image size. Any mismatch is refused (never displays another zone's art) and shown as a fallback state; markers stay on the plain grid.
* Artwork choice is the manifest's own `image` (the importer sets it to the verified full-reveal when available, else base). Cities and a few zones are base-only.
* Lazy: Leaflet, the manifest and the image load only when the map is near the viewport (`lazy`); on small screens the source map is compact with an *Expand map* button.
* The SVG `LocationPlot` is kept as the resilient/accessible fallback: collapsed under the source map, the view when a zone has no atlas art, and a `<noscript>` fallback. It is **not** rendered open next to the map.
* Server pages never depend on the CDN: the directory and zone text use the bundled snapshot when the CDN is unreachable (timeout 2.5 s, 30 s back-off, stale-if-error, 5 min TTL, 2 MB cap, no redirects, strict schema).

### Atlas catalog snapshot

`web/src/lib/maps/atlas/atlas-index.snapshot.json` is the offline fallback only; the CDN catalog is the source of truth. It was generated by `web/scripts/refresh-atlas-snapshot.mjs` from the approved distribution's `atlas/index.json` (sha256 `5d2b2bc110d20f8a3bb24fd2dac8b786ed0ded979de8435bd8bb747ec0cb8e7c`, ZIP `f8a3df96cf9567c8abcd5b80b71d21f6ef44bb09fe455b70b8f32ea75c32c847`, build `1.60.1.70450`). It was **not** fetched from the live CDN by the authoring session (the CDN was unreachable from it). Verify on a machine that can reach the CDN:

```powershell
(Invoke-WebRequest https://azerdex-assets.pages.dev/atlas/index.json -UseBasicParsing).Content | Out-File -Encoding utf8 index.live.json
(Get-FileHash index.live.json -Algorithm SHA256).Hash   # expect 5d2b2bc1...8e7c
```

Inventory (tested): 60 maps = 45 zones + 6 cities + 4 continents + 4 instance maps + 1 world; 105 variants; 45 full-reveal. Duplicate slugs/names exist (`kalimdor`, `eastern-kingdoms`, `zephras-isle` ×2) — slugs are labels, never keys.

Continent grouping uses **verified** parents only (the parent must itself be a continent map in the catalog). Two maps named Zephras Isle exist: 2521 (parent = world map) and 2665 (no parent, 512×512, base art); both are listed, disambiguated by uiMapID, under "Other maps (no verified continent)". The 4 "instance" maps (Alterac Valley, Warsong Gulch, Arathi Basin and **Darkspear Islands** — not a battleground, but classified with them by the exporter) stay out of the zone directory.

## Identifier bridge (audit)

Question: are `ZoneSummary.mapId` / `LocationPoint.mapId` the atlas `uiMapId`? **Yes — evidence:**

1. The addon records `C_Map.GetBestMapForUnit("player")` as `mapId` (`addon/ForeverDB/LocationTracker.lua`, `LootTracker.lua`, `Core.lua`) and coordinates from `C_Map.GetPlayerMapPosition(mapId, "player")` — both are **UiMapID** APIs.
2. `export_locations_v1` / `pub.zones.map_id` / `pub.locations.map_id` carry that value unchanged; the site already labels it "uiMapID" and routes `/zone/<uiMapID>`; `docs/DATA_MODEL.md` lists `map_id / uiMapID`.
3. Fishing sources use the zone's uiMapID as their source id (`/fishing/1420` = "Fishing - Tirisfal Glades"), consistent with (1).
4. Corroboration (test): every zone in the repo fixture resolves to the atlas zone with the **same name** (1411 Durotar, 1412 Mulgore, 1420 Tirisfal Glades, 1421 Silverpine Forest).
5. Not equivalent and never used: the atlas `internalMapId` (client `Map.ID`, e.g. 2991 for both Zephras Isle maps), slugs, `MapArtID`.

`lib/maps/identity.ts` is that bridge: `uiMapId === mapId`, with an explicit `atlas-zone | atlas-other | not-in-atlas` result and an optional zone-name corroboration. Limitation: item 4 was only checkable against the (synthetic) fixture; real published `zone_name` values were not available. A published id that the atlas does not list as a zone/city (a dungeon floor, a sub-map, an unknown id) keeps its text zone page and says "no map artwork"; it is never given another map's art.

## Observation data and privacy review

Sources, in order of use: `web_api.source()` (existing, per source) for source pages; `web_api.zone_map_points(map_id, loot_kind, limit)` (new migration `database/public-read/migrations/0002_zone_map_points.sql`, **not applied anywhere**) for the zone overview. The synthetic POC selector (`lib/maps/zone-observations.ts`) is used by `/poc/maps/tirisfal` only (guarded by a test).

`zone_map_points` reads only `pub.locations` of the **active publication** — cells the publication worker already thresholded (`minLocationCellObservations = 2`, 1% grid, `docs/web/data-classification.md`). Hence it cannot reveal a cell `web_api.source()` does not already reveal. Defence in depth enforced inside the function (tests below):

| Invariant | Mechanism | Test |
| --- | --- | --- |
| no cell below 2 observations, even if a worker misconfigures | `observations >= 2` on every raw cell **before** any summing (two sub-threshold cells never combine into a visible one) | SQL + unit |
| no coordinate finer than the 1% grid | `round(x)`, `round(y)`; coinciding cells summed | SQL + unit |
| no disenchant / item-backed locations | excluded in the query | SQL + unit |
| no contributor/install/account data | none exists in `pub.locations`; output column list is fixed and asserted | unit |
| filters cannot expose withheld cells | per-kind results partition the unfiltered result exactly; every filtered cell ⊆ unfiltered | SQL + unit |
| creature levels stay separate | level is part of the cell identity | unit |
| bounded, cacheable | 1…3000 rows, one zone, one optional kind, fixed deterministic order, 2 s timeout, index `(publication_id, map_id, observations desc)`, in-process TTL cache | SQL + unit |
| read-only, function-only | `EXECUTE` for `foreverdb_web_reader` only; no table grants (boundary assertions inside the migration) | SQL |
| injection | typed bounded parameters; kind is an allow-list; rejected with 22023 | SQL + unit |

Mutation check: 6 deliberately weakened versions of the function (no floor, no re-quantization, disenchant allowed, items allowed, filter ignored, unbounded limit) are each caught by `public_read_zone_map_points.sql`.

**Count semantics.** The zone page's "Located obs." and each source's observation count are *measured* totals; the map shows only *published cells* (≥2 observations, 1% grid). They differ by design. Example (synthetic fixture, Copper Vein `/object/1731`): bucket **121** observations in Tirisfal; located cells **34**, total **104**. The 17 difference are observations without a published location cell. The UI states both numbers separately and never reports a "withheld" figure per filter (that would be a new disclosure). The "121 / 104 / 34" quoted from the Preview screenshot are exactly the **synthetic** fixture values: that Preview serves synthetic sample data.

Residual risks (unchanged by this work, see data-classification.md): 7 installations means thresholds are sample-size controls, not anonymity proofs; the zone overview shows the union of what source pages already show, in one view, which makes dense areas easier to see but adds no cell.

## Coordinates and calibration

Model unchanged (`coordinates.ts`): normalized 0–100, origin top-left, Leaflet `CRS.Simple`, `lat = H·(1−Y/100)`, `lng = W·X/100`. No offsets, mirroring or scaling were introduced.

Every map stays `calibration.status = provisional`. Evidence available and its limit:

| Evidence | Result | What it does **not** prove |
| --- | --- | --- |
| Manifest image size = client layer extent (full canvas), all 51 zone/city maps | 51/51 equal (50 × 1002×668, 1 × 512×512) | landmark registration |
| Client `UiMapAssignment`: exactly one assignment per map covering `uiMin (0,0) – uiMax (1,1)`, all 51 | 51/51 | that observed X/Y land on the right landmark |
| Tirisfal v2 vs the owner-supplied reference image (exporter's `registration`) | `matches-reference`, shift (0,0), mean error 4.53 | landmark validation |
| Marker ↔ artwork registration through zoom/pan/resize/rotation (browser) | within 1.5 px of the model on the rendered image, desktop+mobile | geographic truth |

**Real-data calibration was NOT performed.** The authoring environment had no access to genuine published located observations (the only data in the repository is a synthetic fixture, whose coordinates are invented) and no independent landmark list. Per the brief nothing is marked validated and no PASS is claimed. Procedure to run when real data is reachable: pick ≥3 zones with dense published cells of different kinds (e.g. Tirisfal, Mulgore, Durotar); for each, plot with this page, compare ≥6 verifiable in-game positions (flight masters, inns, zone-edge towns) to the plotted cells, record per-landmark offsets, look for a constant shift / axis flip / scale; only a documented pass moves a map to `validated` (a new immutable atlas version).
