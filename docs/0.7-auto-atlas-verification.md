# ForeverDB Companion — Auto Atlas Verification

Status (2026-10-09): **PR #21 code/Windows CI PASS, 70291 network DB2 proof 84/84 PASS, Tirisfal #2126 real Windows fresh/warm fully revealed map PASS; Mulgore #1200, Silverpine #2158 and remaining runtime/HTTP gates OPEN.** No approval based on a higher build number alone.

## Rationale and sources

Following the Forever beta update from 1.60.1.70245 to **1.60.1.70291**, the pinned allowlist correctly reverted to the base map. The addon provides `C_Map` base art but not the complete *unexplored* WorldMapOverlay region catalogue.

New-build verification downloads the **exact installed version's public DB2 CSV** exports over HTTPS from `https://wago.tools`:

- `WorldMapOverlay`: map art ID, rectangle, offset, player conditions
- `WorldMapOverlayTile`: overlay ID, row, column, layer, FileDataID
- `UiMapArt`: map art / style
- `UiMapArtStyleLayer`: style, layer number, tile dimensions

The Companion sends only the numeric **version** to the public source; it never uploads player data, Build Key, credentials, source files or artwork. The product must be an **active wow_classic_beta** installation with a well-formed version and Build Key.

## Strict equality, not optimistic compatibility

1. Parse **all four complete CSVs** using a bounded (16 MiB per file), quoted-field-safe CSV reader. Reject missing columns/files, invalid numeric fields, duplicate IDs, orphan tiles, conditional overlays, unsupported layers, invalid dimensions, duplicate tile coordinates or incomplete 256px grids.
2. Reconstruct region geometry and *ordered*, row-major FileDataIDs for every art ID.
3. Compare each art to **all** of its entries in the embedded 70009 MIT-sourced atlas, including map ID, X/Y, width/height and ordered tile IDs. Only **identical map arts** are admitted, even when the new build introduces additional or changed map arts.
4. The renderer still requires the exact native 1002×668, 256px base layer, complete decodable base tiles and **every** revealed tile from the installed CASC or exact active-build Blizzard CDN. A missing/corrupt tile rejects the entire full-map variant and falls back to the original base map.
5. UI markers, clusters, heatmap, search zone scope, normalized X/Y projection and Back/Forward remain independent of this art-only change.

**No blind 1.60.* approval.** File existence alone is not a verified atlas. An unavailable, unindexed, incompatible or malformed source never promotes a new build.

## Proof cache and network rules

- Verification requests are deduplicated per **product + version + exact Build Key + SHA256(atlas)**, including concurrent map loads.
- Successful per-map-art proofs are cached as hashed identities (no original Build Key) in `%LOCALAPPDATA%\ForeverDB\maps\atlas-verified-builds.json` and reused up to **14 days**.
- Failed or temporarily unavailable online checks retry after **15 minutes**, or immediately when the user clicks `Retry map`.
- Four size-limited downloads share an **18-second** timeout. The build-key-specific proof is required before any `full-auto-verified-...` PNG variant/cache is used. A changed build or embedded atlas invalidates its identity.
- Existing 1.60.1.70009 and 1.60.1.70245 reviewed builds keep the original **offline fast path** without fetching DB2s.
- Remote metadata is used **only for verification**; no downloaded FileDataID or executable code is used as live art or a replacement atlas. Real art comes from the exact active local `wow_classic_beta` product or the exact matching build's CDN. The old unpinned `CascOpenOnlineStorage` "latest build" fallback has been removed, and classic named-texture fallback remains available for **base art only**, not to auto-verify a new build.
- This implementation depends on wago.tools remaining available and indexing the exact new build. A later **local offline CASC DB2 reader** could remove this availability dependency.

## Automated regressions

Portable `tests/companion-map-reveal` reconstructs all four source tables from the embedded atlas (84 maps, 1,073 regions, 1,739 tiles), then checks full equality and selective mismatch (83/84), missing/duplicated/conditional tiles, corrupt/missing CSV columns, quoted CSV, wrong client product/version/key, per-build proof key isolation and prior rendering/cache regressions. Windows `Companion health checks` builds WPF and runs the regression suites.
